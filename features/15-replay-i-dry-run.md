# 15. Ручной replay и dry-run

**Приоритет:** 🟡 средний · **Трудоёмкость:** S

> Актуализация (2.0/3.0): с журналом (#05) и store-and-forward фича сильно
> подешевела — replay это сброс записи `relayed_messages` обратно в pending,
> доставку добьёт штатный `mailspoon:deliver`; читать письмо из ящика заново
> не нужно, сырой MIME лежит в архиве (#19). Команды — `mailspoon:replay` /
> `mailspoon:test`.

## Проблема

Если письмо не дошло (эндпоинт лежал) или нужно повторно прогнать конкретное
сообщение после починки приёмника — переотправить нечем. Единственный способ
сейчас — снять флаг `\Seen` в почтовом клиенте и ждать следующего `imap:pull`.
Также нет «сухого прогона», чтобы безопасно проверить настройку, не дёргая
боевой эндпоинт.

## Цель

Команды для повторной отправки конкретных писем и для безопасной проверки
конфигурации без реальной доставки.

## Предлагаемое решение

**Replay** — переотправить по `Message-Id` или из журнала проваленных (#05):

```bash
php artisan spoon:replay <message-id>          # одно письмо
php artisan spoon:replay --failed              # все failed из журнала
php artisan spoon:replay --mailbox=default --since=2026-06-01
```

Реюзает тот же путь доставки, что и listener (диспатч задачи из #01).

**Dry-run** — прогон без фактического POST: показывает, что и куда ушло бы,
печатает сформированный payload и подпись, но `Http`/`markSeen` не вызывает:

```bash
php artisan imap:pull default --dry-run
php artisan spoon:test default                 # взять последнее письмо, показать payload
```

Реализация dry-run: флаг прокидывается в listener; при нём вместо `Http::post`
и `markSeen()` — вывод в консоль/лог.

## Изменения конфигурации

Флаги команд, отдельной конфигурации не требуется.

## Замечания

- `spoon:replay --failed` опирается на журнал из #05; без него — только по
  `Message-Id` напрямую из ящика.
- Dry-run отлично помогает при настройке подписи/совместимости с получателем.
- Replay должен уважать дедуп (#05): по умолчанию — переотправлять (явное
  действие оператора), но логировать факт.

## Definition of Done

- [ ] `spoon:replay` по `Message-Id` и по `--failed`.
- [ ] `--dry-run` не делает реальных POST и не помечает письма.
- [ ] `spoon:test` показывает готовый payload и подпись.
