# 07. Мониторинг и здоровье воркера

**Приоритет:** 🟢 низкий · **Трудоёмкость:** M

## Проблема

`imap:sentry` — долгоживущий процесс на IMAP IDLE. Если он тихо упал, потерял
соединение или эндпоинт стабильно отвечает ошибкой, узнать об этом сейчас
неоткуда: ни heartbeat, ни метрик, ни алертов. Письма просто перестают
доставляться.

## Цель

Наблюдаемость: сигнал «я жив», health-check для оркестратора, базовые метрики и
алерт при деградации доставки.

## Предлагаемое решение

1. **Heartbeat.** В цикле watch обновлять метку времени (кэш/файл) и, опц.,
   пинговать внешний health-сервис:

   ```php
   Cache::put('spoon:heartbeat:'.$mailbox, now(), ttl: 120);
   // опц. Http::get(config('spoon.heartbeat_url'));
   ```

2. **Команда health-check** для контейнера/оркестратора:

   ```bash
   php artisan spoon:health   # exit 0 если heartbeat свежий, иначе 1
   ```

   Подходит как Docker `HEALTHCHECK` (см. #09).

3. **Метрики** из таблицы журнала (#05): доставлено/провалено за период,
   среднее число попыток, последний код ответа. Отдавать команду
   `spoon:stats` и/или JSON-эндпоинт `/health`.

4. **Алерты** при провале доставки (`failed()` из #01): уведомление в
   Slack/почту/webhook через стандартные Laravel Notifications.

## Изменения конфигурации

```dotenv
SPOON_HEARTBEAT_URL=https://hc-ping.com/uuid   # опционально
SPOON_HEARTBEAT_TTL=120
SPOON_ALERT_WEBHOOK=https://hooks.slack.com/...
```

## Замечания

- Метрики зависят от #05 (журнал) — без БД считать не из чего, кроме грубого
  счётчика в кэше.
- Health-check exit-кодом — простейшая интеграция с systemd/Docker/K8s.

## Definition of Done

- [ ] Heartbeat обновляется в цикле watch.
- [ ] `spoon:health` возвращает корректный exit-код.
- [ ] Алерт при окончательном провале доставки.
- [ ] (Опц.) `spoon:stats` со сводкой из журнала.
