примерный приоритет: чем меньше номер, тем выше отдача.

## Сводный взгляд

**Сделано в 2.0.0** — архитектура store-and-forward: приём (`imap:*`) сохраняет
письмо в хранилище и фиксирует в `relayed_messages`, доставку отдельно выполняет
`spoon:deliver` по планировщику.

- **#05** (журнал + дедуп) и **#19** (архив) — ядро store-and-forward.
- **#01** (надёжная доставка) — влита в `spoon:deliver` (двухуровневый ретрай).
- **#16** (планировщик) — `withoutOverlapping`, режим cron-poll.
- **#08** (тесты) — частично: есть Pest-покрытие захвата/доставки/ретрая/
  планировщика; CI-workflow ещё нет.

**Сделано в 3.0.0** — конверсия в composer-пакет `ttbooking/mailspoon` (#21):
код в `src/`, публикуемый `config/mailspoon.php`, команды `mailspoon:*`,
тесты на testbench. Хвосты: публикация на Packagist и миграция прода на
тонкое хост-приложение.

**Переоценка после перехода на пакет.** Инфраструктуру теперь даёт
хост-приложение, поэтому часть фич девальвировалась:

- **#09** (деплой/Docker) — деплой стал собственностью хоста, примеры
  supervisor/cron уже в README пакета → 🔀 #21;
- **#07** (мониторинг) — не строить свою наблюдаемость, а встроиться в
  хостовую (чеки для spatie/laravel-health), трудоёмкость M → S;
- **#12** (дашборд) — либо UI в стиле Horizon (дорого), либо хост сам строит
  экран поверх модели `RelayedMessage` → ждём реального запроса;
- **#20** (graceful shutdown) — главный риск (дубли) закрыт store-and-forward
  и дедупом #05, остался аккуратный выход по SIGTERM в IDLE-режиме → 🟢.

Эскизы, написанные до 2.0/3.0 (#02, #04, #10, #14, #20), при реализации
актуализировать: фильтры/антиспам применяются при захвате
(`StoreIncomingMessage`), payload/rate-limit — при доставке
(`mailspoon:deliver`), настройки — массивы в опубликованном конфиге, а не
env-сериализация.

**Сделано после 3.0.0** — #03 фаза 1 (маршрутизация): карта `routes` в
опубликованном конфиге, эндпоинт резолвится при захвате, ключ — при доставке;
дедуп по `(mailbox, target, fingerprint)`. Фаза 2 (fan-out) отложена.

**Сделано после 3.1.0** — #15 (`mailspoon:replay` + `mailspoon:deliver
--dry-run`) и #17 (`mailspoon:doctor`); отдельная `mailspoon:test` из эскиза
#15 не понадобилась.

**Сделано после 3.2.0** — #04 (фильтрация: `filters` allow/deny) и #22
(ящики-люди: `mark` = seen/keyword/none, UID-курсор) — вместе закрывают
сценарий «ящик операторов».

**Сделано после 3.3.2** — наблюдаемость реле: события `MessageFiltered` и
`DeliveryPermanentlyFailed` + лог-записи (закрывают «алерты» из #07 — само
уведомление вешает хост), заголовки `X-Mailspoon-Message-Id`/`-Attempt` для
дедупа на приёме, README про at-least-once. Остаток наблюдаемости фильтра
вынесен в #23.

**Ближайшие кандидаты дальше:** хвост #21 (миграция прода; Packagist
опубликован, CI добавлен — #08 ✅) → #11 (OAuth2 — отложена, разведка в файле
фичи) → #14+#02 связкой (форматтеры + полный payload).
Retention-хвосты из #05/#19 объединены: Eloquent `Prunable` удаляет запись
и MIME совместно.
