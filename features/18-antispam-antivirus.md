# 18. Антиспам / антивирус

**Приоритет:** 🟢 низкий · **Трудоёмкость:** M

> Актуализация (2.0/3.0): проверка — при захвате (`StoreIncomingMessage`), до
> записи в журнал и архив; реакции — словарь действий из
> [#06](06-deystviya-posle-relay.md); настройки — массив в опубликованном
> `config/mailspoon.php`, env-переменные из эскиза не нужны.

## Проблема

Mailspoon пересылает любое письмо, включая спам и потенциально вредоносные
вложения, прямо во внутренние системы-получатели. Для ящика, открытого вовне
(`support@`, `info@`), это канал доставки нежелательного/опасного контента в
обход почтовых защит — особенно если получатель доверяет «входящему вебхуку».

## Цель

Оценка письма на спам/вредоносность до пересылки с настраиваемой реакцией:
пропустить с пометкой, отбросить, увести в карантинную папку.

## Предлагаемое решение

Использовать уже посчитанные провайдером заголовки и/или внешние сканеры:

1. **По заголовкам** (дёшево, без зависимостей) — читать
   `X-Spam-Status`/`X-Spam-Score` (SpamAssassin), `Authentication-Results`
   (SPF/DKIM/DMARC), порог по score:

   ```php
   $score = $message->header('X-Spam-Score');
   if ($score !== null && (float) $score >= config('spoon.spam.threshold')) {
       // действие из конфига
   }
   ```

2. **Внешний сканер** (опционально) — отдать сырой MIME в rspamd/ClamAV по
   API/сокету и решить по вердикту. Реализовать как подключаемый `ScanDriver`.

Реакция на «грязное» письмо — переиспользует действия из #06:

```php
'spam' => [
    'threshold' => 5.0,
    'on_spam'   => 'move:Spam',      // pass | tag | drop | move:<folder>
    'on_virus'  => 'move:Quarantine',
],
```

При `tag` — добавить поле в payload (`X-Spam: yes`), чтобы получатель решал сам.

## Изменения конфигурации

```dotenv
SPOON_SPAM_THRESHOLD=5.0
SPOON_SPAM_ACTION=move:Spam
SPOON_VIRUS_SCANNER=                 # пусто | rspamd | clamav
SPOON_VIRUS_SCANNER_DSN=tcp://127.0.0.1:11334
```

## Замечания

- Без внешнего сканера фича всё равно полезна за счёт заголовков, которые часто
  уже проставлены MTA.
- Близко к #04 (фильтрация), но это про безопасность/репутацию, а не про
  бизнес-правила — держать раздельно, действия общие (#06).
