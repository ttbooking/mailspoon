# 23. Наблюдаемость фильтра: dry-run и журнал отфильтрованного

**Приоритет:** 🟢 низкий · **Трудоёмкость:** M

> Контекст: первый уровень наблюдаемости фильтра уже есть (3.4.0) — каждое
> отфильтрованное письмо объявляется событием `MessageFiltered` и по умолчанию
> пишется в лог Laravel дефолтным слушателем `LogFilteredMessage` (отключается
> `MAILSPOON_LOG_FILTERED=false`). Этот файл — про следующие два уровня, если
> лога и события окажется мало.
>
> 🔶 Часть 1 реализована в 3.9.0, но иначе, чем в эскизе ниже: вместо «последних
> N писем из ящика» — одно письмо из `--file` (сырой MIME, без IMAP) или `--uid`.
> Логика в сервисе `FilterTester` (структурный `FilterTestResult` для дашборда),
> работает на выключенном ящике. Часть 2 (queryable-журнал отфильтрованного) —
> по-прежнему предложение.

## Проблема

Правила `filters` применяются на проде вслепую: `mailspoon:doctor` проверяет
только синтаксис (битый регэксп, неизвестное поле), но не показывает, *что*
правила отфильтруют на реальных письмах. Ошибка в `allow`-регулярке видна
по логу/событию уже постфактум — когда письма начали отбрасываться. Хочется
проверить matching заранее и иметь queryable-историю отфильтрованного.

## Предлагаемое решение

### Часть 1. `mailspoon:filter-test` — сухой прогон правил

```bash
php artisan mailspoon:filter-test default --limit=50
```

Подключается к ящику, забирает последние N писем (chunked fetch, как в
`mailspoon:pull`) **без side-эффектов** — не помечает, не журналирует, не
двигает курсор — и печатает таблицу: From / Subject / Message-Id / вердикт
(allow / deny / no-match). Использует тот же `MessageMatcher::for($mailbox)`,
что и боевой захват, так что вердикты идентичны проду.

Тонкости:

- фетчить только заголовки (`withHeaders()`), тело — лишь когда правила
  содержат `has_attachment` (нужна структура);
- `--limit` ограничивает выборку с конца (свежие письма интереснее);
- exit-код всегда 0 — команда информационная, не препятствие деплою.

### Часть 2. Опциональный журнал отфильтрованного

Флаг `MAILSPOON_JOURNAL_FILTERED=true`: отфильтрованное письмо получает запись
в `relayed_messages` со статусом `filtered` — только заголовки (from / subject
/ message-id / mailbox), **без архива MIME** (дёшево). Это даёт queryable-след
(сколько и что отброшено по каждому ящику) и материал для дашборда (#12).

Стоимость, из-за которой это не сделано сразу:

- новый статус надо исключить из `deliverable()`, `replay --failed`,
  доктора и учесть в `prunable()` (чистить по received_at, а не delivered_at);
- дедуп: запись `filtered` не должна блокировать повторный захват, если
  правила исправили и письмо теперь проходит (фингерпринт совпадёт!) —
  вероятно, дедуп-проверку придётся ограничить незавершёнными статусами
  или чистить `filtered`-записи при изменении правил.

## Изменения конфигурации

```dotenv
MAILSPOON_JOURNAL_FILTERED=false   # часть 2, по умолчанию выключено
```

## Definition of Done

- [ ] `mailspoon:filter-test {mailbox} --limit=N` печатает вердикт по каждому
      письму без side-эффектов.
- [ ] (Часть 2) записи `filtered` создаются под флагом, не ломают доставку,
      replay, доктора и prune.
- [ ] Дедуп не блокирует повторный захват письма после исправления правил.
