# 13. Fan-out на несколько эндпоинтов

**Приоритет:** 🟡 средний · **Трудоёмкость:** M

## Проблема

Одно письмо можно отправить только на один URL (`spoon.endpoint`). А типичная
потребность — доставить одно и то же письмо **в несколько систем сразу**:
например, в основной обработчик `laravel-mailbox`, в архивный сервис и в
аналитику. Сейчас это требует, чтобы получатель сам раздавал копии.

## Цель

Веер доставки: одно входящее письмо → N независимых вебхуков, у каждого свой URL
и ключ подписи, с независимыми статусами и ретраями.

## Предлагаемое решение

Расширить конфиг до списка назначений (надстройка над #03):

```php
'destinations' => [
    ['endpoint' => env('SPOON_ENDPOINT'),     'key' => env('SPOON_KEY')],
    ['endpoint' => env('SPOON_ARCHIVE_URL'),  'key' => env('SPOON_ARCHIVE_KEY')],
    ['endpoint' => env('SPOON_ANALYTICS_URL'),'key' => env('SPOON_ANALYTICS_KEY'),
     'payload' => 'full'],   // у каждого может быть свой формат (#14)
],
```

Listener разворачивает по одной очередной задаче на назначение (а не один
запрос с несколькими POST) — чтобы провал одного не влиял на остальные и каждый
ретраился отдельно (#01):

```php
foreach (config('spoon.destinations') as $dest) {
    DeliverToEndpoint::dispatch($event->message, $dest);
}
// markSeen — только когда ВСЕ назначения подтвердили доставку
```

`markSeen()` — после успеха всех (или по политике «достаточно одного»).

## Изменения конфигурации

```dotenv
SPOON_ARCHIVE_URL=https://archive/.../mime
SPOON_ARCHIVE_KEY=key-...
SPOON_FANOUT_POLICY=all     # all | any  (когда считать письмо обработанным)
```

## Замечания

- Сильно завязано на #01 (очередь/ретраи) и #05 (статус на каждое назначение).
- Политика `all` против `any` влияет на момент `markSeen` — выбрать осознанно.
- У каждого назначения может быть свой payload-формат (#14).

## Definition of Done

- [ ] Одно письмо доставляется на список назначений.
- [ ] Независимые ретраи/статусы на каждое.
- [ ] Политика `all`/`any` для пометки прочитанным.
- [ ] Back-compat с одиночным `endpoint`.
