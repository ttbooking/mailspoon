# 22. Ящики-люди: захват без пометки прочитанным

**Приоритет:** 🔴 высокий (есть реальный сценарий) · **Трудоёмкость:** S–M
(+ #04 для фильтра)

> Источник: задача «следить за ящиком операторов, разбирать тему, искать
> особый символ и обрабатывать совпавшие письма — не помечая их прочитанными».
> Зависит от [#04](04-filtraciya-pisem.md) (фильтр по теме); пересекается с
> [#06](06-deystviya-posle-relay.md) (словарь действий, `leave`).

## Проблема

Mailspoon заточен под «ящик-робот»: флаг `\Seen` — его курсор «обработано»,
выборка — `unseen()`, после захвата — `markSeen()`. Для «ящика-человека»
(общий ящик операторов) это неприемлемо: прочитанность принадлежит людям,
mailspoon не должен её трогать. Но просто убрать `markSeen()` нельзя — без
курсора каждый pull будет заново выкачивать все непрочитанные письма ящика.

Ключевой факт: ImapEngine читает письма через **BODY.PEEK** — само скачивание
тел ничего не помечает. Прочитанным письмо делает только наш явный
`markSeen()` в `StoreIncomingMessage`. Значит, задача сводится к замене
курсора, а не к борьбе с протоколом.

## Цель

Настраиваемый «маркер обработанного» на ящик: чем mailspoon отмечает для себя
просмотренные письма и как выбирает непросмотренные — не затрагивая
прочитанность.

## Предлагаемое решение

Опция `mark` на маршруте (или глобально):

```php
'routes' => [
    'operators' => [
        'endpoint' => 'https://crm.example.com/api/mailgun/mime',
        'key' => 'key-operators',
        'mark' => 'keyword:Mailspoon',   // seen (дефолт) | keyword:<имя> | none
        'filters' => [                   // из #04
            'allow' => ['subject' => ['/⚡/u']],
        ],
    ],
],
```

### Вариант A: кастомный IMAP-keyword (основной)

IMAP позволяет вешать пользовательские кейворды рядом с системными флагами.
Всё нужное уже есть в ImapEngine:

- выборка: `unkeyword('Mailspoon')` вместо `unseen()`
  (`ImapQueryBuilder::unkeyword()`);
- маркировка: `$message->flag('Mailspoon', '+')` вместо `markSeen()`
  (`HasFlags::flag()`).

Свойства: операторы ничего не замечают (клиенты не показывают кастомные
кейворды), прочитанность не трогается, курсор живёт на сервере — переустановка
mailspoon или второй инстанс ничего не ломают.

Требование: сервер должен разрешать кастомные кейворды
(`PERMANENTFLAGS \*` в ответе SELECT — Dovecot, Gmail, Exchange умеют).
Проверку добавить в `mailspoon:doctor` (#17).

### Вариант B: UID-курсор в БД (fallback)

Для серверов без кастомных кейвордов (`mark => 'none'`): таблица
`(mailbox, folder, uidvalidity, last_uid)`, выборка `uid(last + 1, '*')`
(`ImapQueryBuilder::uid()`). Обязательно сверять `UIDVALIDITY` — при смене
курсор сбрасывается. Минус: курсор у нас, а не на сервере.

В обоих вариантах дедуп по `(mailbox, target, fingerprint)` (#05) остаётся
второй линией обороны от двойной обработки.

### Семантика: «просмотрено» ≠ «переслано»

При курсоре-keyword маркер ставится **всем** просмотренным письмам — иначе
несовпавшие с фильтром будут перечитываться каждым pull. В журнал и доставку
идут только совпавшие с фильтром #04; действие для отфильтрованных — `leave`
(словарь #06), `\Seen` не трогается ни у кого.

### Точки правки

- `StoreIncomingMessage`: `markSeen()` → `$this->mark($message, $mailbox)` по
  опции маршрута (включая ветку дедупликации, где сейчас тоже `markSeen()`);
- `mailspoon:pull`: выборка `unseen()` → по опции маршрута
  (`unseen` / `unkeyword(...)` / `uid(...)`);
- `mailspoon:sentry`: pre-fetch наследует выборку pull; IDLE-события от
  `imap:watch` реагируют на новые письма независимо от флагов — менять нечего;
- `mailspoon:doctor`: проверка `PERMANENTFLAGS \*` для ящиков с
  `mark => keyword:*`.

## Изменения конфигурации

Ключ `mark` в маршруте (см. выше) и/или глобальный `mailspoon.mark`.
Значения: `seen` (дефолт, текущее поведение), `keyword:<имя>`, `none`
(UID-курсор).

## Замечания

- Сценарий «ящик операторов» целиком = #22 (курсор) + #04 (фильтр по теме) +
  маршрут #03 на эндпоинт обработчика. Реализовывать #22 и #04 связкой.
- `keyword:` уже упоминался в #06 как действие `flag:<name>` — это тот же
  механизм, но здесь он курсор, а не пост-действие.
- Replay (#15) и доставка не затрагиваются: они работают с журналом и архивом,
  в ящик не ходят.

## Definition of Done

- [ ] Опция `mark` (глобально и на маршрут): `seen` / `keyword:<имя>` / `none`.
- [ ] `keyword:` — выборка `unkeyword`, маркировка кастомным кейвордом,
      `\Seen` не трогается (включая ветку дедупа).
- [ ] `none` — UID-курсор с проверкой `UIDVALIDITY`.
- [ ] Маркер ставится всем просмотренным; пересылаются только прошедшие
      фильтр #04 (отфильтрованные — `leave`).
- [ ] `mailspoon:doctor` проверяет поддержку кастомных кейвордов сервером.
- [ ] Тесты: выборка по опции, маркировка без `\Seen`, повторный pull не
      перечитывает просмотренное.
